## [Unreleased]

## [0.6.0] — 2026-08-13

### Added
- **Удалённый журнал SDK (`SdkLogger`).** Каждый внутренний шаг SDK —
  `configure`, ветки `identify` (кэш-guid / резолв токена / email-fallback),
  запрос права, открытие пейвола/квиза, события JS-моста, возвратный deep-link,
  APP_INSTALLED-callback и все ошибки сети с HTTP-кодами — теперь пачками
  отправляется на наш бэкенд (`POST /public/sdk-logs`) и дублируется в
  Xcode-консоль (`print` с префиксом `[Web2App]`). Это диагностика интеграций:
  раньше «что происходит внутри приложения интегратора» было видно только по
  логам Xcode с его стороны. Отправка fire-and-forget с дебаунсом 3 с и капом
  буфера — сбой сети или бэкенда никак не влияет на работу SDK. PII не уходит:
  email не логируется (только факт «email передан»), guid — наш собственный
  client-held идентификатор.

### Changed
- **Уточнено поведение связки `guid` ↔ profile-id на стороне сервера** (только
  документация; поведение SDK не менялось). Страница пишет значение лишь в
  ПУСТОЙ слот: заменить уже сохранённое через страницу нельзя (только серверной
  ручкой `POST /s2s/v1/identity/link-profile`), а дописать вторую платформу
  можно только вместе с верными значениями всех уже занятых слотов. Отказ
  молчаливый — сервер отвечает «успех» в любом случае (защита от перебора
  плательщиков). **Рецепт для интеграторов:** передавать ОБА идентификатора
  (`adaptyProfileId` и `revenuecatProfileId`) при КАЖДОМ открытии страницы —
  прежняя формулировка «связку с guid делает сервер сам, отдельную ручку звать
  не надо» (запись 0.5.0 ниже) вводила в заблуждение. Отдельно: наш `guid`
  нельзя использовать как profile-id платформы (`Purchases.logIn(<guid>)`) —
  с ним дозапись второй платформы через страницу не сработает никогда.
- **Исправлен образец интеграции AppsFlyer** в doc-комментарии
  `AttributionResolver` и в README: токен опознания лежит в `deep_link_sub1`
  (дубль — `af_sub1`), а в `deep_link_value` бэкенд кладёт константу `handoff`.
  Кто копировал старый образец, получал строку `handoff` вместо токена.

## [0.5.0] — 2026-08-12

Паритет с Android SDK 0.5.0. Минор, а не патч: добавлена функциональность —
события прохождения воронки наружу, встроенный показ квиза, profile-id
подписочных платформ в URL страницы.

### Added
- **События воронки из WebView-моста** — `Web2App.setFunnelEventListener(_:)`.
  Наружу идут `quiz_start`, `quiz_screen_view`, `quiz_answer`,
  `quiz_email_submit`, `quiz_complete`, а также `paywall_result` со
  `status == "dismissed"`. Слушатель один на SDK, снимается передачей `nil`;
  колбэк вызывается на главном потоке.
- **`Web2App.openQuizEmbedded(quizURL:email:completion:)`** — открытие квиза
  встроенным WKWebView (тот же экран и тот же мост, что у пейвола). Принимает
  ГОТОВЫЙ URL квиза: ручки резолва URL по ID на бэкенде нет, аналога
  `openWebPaywallEmbedded(paywallId:)` тут не существует. Результат — не оплата,
  а факт закрытия: `QuizResult.closed(reason)` с `QuizCloseReason.page` /
  `.user` / `.paid`, либо `.unavailable` (SDK не сконфигурирован — экран не
  показали). Событие `quiz_complete` окно НЕ закрывает: квиз ведёт дальше.
  Право в квиз-режиме SDK не поллит — за грантом идите в `entitlement`.
- **profile-id подписочных платформ в URL** — у всех методов открытия (и
  пейвола, и квиза) появились опциональные `adaptyProfileId:` /
  `revenuecatProfileId:`. SDK дописывает их в URL страницы как
  `adapty_profile_id` / `revenuecat_profile_id`; связку с guid делает сервер
  сам, отдельную ручку звать не надо.

### Changed
- ⚠ **Изменение поведения моста.** Раньше ЛЮБОЕ распознанное событие моста
  закрывало встроенный WebView. Теперь закрывают ровно два —
  `paywall_result` со `status == "success"` и `close`; всё остальное (включая
  `paywall_result:dismissed` и все `quiz_*`) окно не трогает. Незнакомые события
  игнорируются, поэтому старые интеграции работают без правок.
- ⚠ **Порядок параметров у методов открытия.** `adaptyProfileId:` и
  `revenuecatProfileId:` встали ПЕРЕД `completion:`. У обоих есть значение по
  умолчанию (`nil`), так что вызов с явными метками аргументов
  (`openWebPaywall(paywallURL:…, completion:)`) продолжает компилироваться —
  в Swift метки обязательны, поэтому «позиционного» слома, как в Android-версии,
  тут нет. Но если вы храните метод как значение (`let f = Web2App.openWebPaywall`)
  или передаёте его как замыкание — тип функции изменился, место придётся
  поправить.

### Fixed
- **Починен парс ответа `GET /public/handoff/resolve?code=`**: guid лежит внутри
  обёртки `{"success":true,"data":{...}}`, а читался с верхнего уровня. Фикс
  приехал уже после тега `0.4.3` и в предыдущий релиз не попал.

## [0.4.3] — 2026-07-24

### Changed
- Кнопка закрытия в embedded-режиме: тёмный круг заменён на размытую подложку
  (frosted glass, `.systemThinMaterial`) — не давит тёмным пятном на светлом
  фоне, крестик (`.label`) адаптируется к теме и остаётся читаемым.

## [0.4.2] — 2026-07-24

### Fixed
- Встроенный WebView-режим: нативная кнопка закрытия (крестик) сливалась со
  светлым фоном пейвола и была почти невидима. Заменена на контрастную —
  белый крестик на тёмном полупрозрачном круге, видно на любом фоне.

## [0.4.1] — 2026-07-24

### Fixed
- **Safari-режим: свайп-закрытие шторки «терял» completion навсегда** —
  SFSafariViewController теперь показывается `.fullScreen` (свайп недоступен),
  плюс делегат `presentationControllerDidDismiss` как страховка: любое
  интерактивное закрытие корректно завершает флоу и запускает поллинг.
- Колбэки `openWebPaywall`/`openWebPaywallEmbedded` теперь всегда приходят
  на main-потоке (раньше могли прилететь с фонового потока URLSession).
- Повторный вызов open* при уже открытом пейволе больше не осиротляет
  completion первого вызова: предыдущий презентер корректно завершается.
- WKWebView-режим: script-handler `web2app` снимается явно при завершении
  (защита от retain-цикла WKUserContentController).
- Embedded-режим: окно поллинга после события `close` выровнено с окном
  после успеха (10 попыток × 1с) — закрывший юзер с медленным вебхуком
  больше не получает мгновенный `.notPaid`.

### Added
- `PaywallResult.unavailable` — «пейвол не был показан» (SDK не
  сконфигурирован / платформа без UIKit / не разрезолвился paywallId);
  раньше это маскировалось под `.notPaid`.

## [0.4.0] — 2026-07-24

### Added
- `Web2App.openWebPaywall(paywallId:...)` — открытие пейвола по его ID:
  SDK сам резолвит публичный URL через `GET /public/paywall-url/:paywallId`.
- `Web2App.openWebPaywallEmbedded(paywallURL:/paywallId:...)` — встроенный
  WKWebView-режим с JS-мостом: при успехе оплаты пейвол закрывается
  автоматически, кнопка «Закрыть» обрабатывается без URL-схемы.
- `PaywallResult` — типизированный результат: `.paid(grant)` / `.notPaid` /
  `.pending` (вместо неоднозначного `EntitlementGrant?`).

## [0.3.0] — 2026-07-24

### Added
- `Web2App.handleReturnURL(_:)` — обработка возвратного deep-link'а кнопки
  «Закрыть» с веб-пейвола (`<схема>://handoff?code=...`): закрывает шторку
  SFSafariViewController и немедленно запускает guid-поллинг доступа —
  пользователь возвращается в приложение уже «платным». README: инструкция
  по регистрации URL-scheme и настройке «Схемы возврата» в кабинете.

## [0.2.0] — 2026-07-23

### Added
- `Web2App.openWebPaywall(paywallURL:email:completion:)` — обратный флоу
  app→web-paywall: пользователь в приложении открывает веб-пейвол и после
  оплаты получает доступ. После закрытия пейвола SDK поллит entitlement и
  возвращает грант в completion (WEB-525).

## [0.1.0]

- Первый публичный релиз iOS SDK: `configure`, `identify(deepLinkValue:)`,
  `requestEmailRecovery`, `entitlement`, `currentGuid`.
